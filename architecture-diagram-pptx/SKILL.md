# 用 PowerPoint 做架构图

把系统结构画成一张能直接放进评审材料、白皮书、答辩 PPT 的架构图。成品是两个文件：可编辑的 `.pptx` 和供快速确认的 `.png`。

## 交付物

1. `<图名>.pptx` —— 所有模块、连线、文字都是 PowerPoint 原生对象，用户能直接改字、挪框、换色。
2. `<图名>.png` —— 由这个 pptx 导出的预览图，长边 ≥ 2000px。
3. 3—5 行说明：分层结构、配色语义、假设项、两个文件各自的用途。

## 铁律

- **只用原生对象。** 矩形/圆角矩形/直线连接线/文本框。不得把整张图当图片贴进去，不得把文字转成轮廓或图片。判断标准：用户在 PowerPoint 里点一下模块，能改字。
- **PNG 只能由最终 PPTX 经 PowerPoint COM 导出。** 不要用 LibreOffice——本机已卸载，而且它渲染的字体度量与 PowerPoint 不一致，导出的图和 pptx 打开后不一样。导出脚本已封装在 `archbuild.py` 里，不要自己另写一条渲染管线。
- **不要手写几百行 python-pptx 摆盒子。** 本技能自带渲染器，你只负责写 JSON 规格。手写坐标的图几乎必然出现文字溢出、连线穿框、间距不均。
- **交付前必须自己看一遍 PNG。** 用 Read 工具直接读图片。不看图的交付等于没验收。

## 工作流

1. **提炼结构。** 从需求、代码、文档或截图中抽出四样东西：系统边界（谁在框里、谁在框外）、分层方式、模块清单、模块间的依赖或数据流。信息不足时按合理假设先做，把假设写进 `notes`，不要为了"完整"编造模块。
2. **选图型。** 见 `references/design-spec.md` 的图型配方：分层架构（最常见）、中心辐射、部署拓扑、模块树、数据流。选错图型比画得丑更致命。
3. **写规格。** 一个 JSON 文件，描述标题、分层、分组、模块、连线、图例、注释。字段见下方速查，完整定义见 `references/spec-schema.md`。
4. **构建。** `build` 子命令会自动做布局、文字适配、连线避障和自检，输出 pptx；加 `--png` 同时导出预览图。
5. **看图。** 读 PNG，检查四件事：文字有没有溢出或截断、连线有没有压住模块、标签有没有叠在一起、层级是否一眼能分辨。有问题改规格重跑，不要手动改 pptx。
6. **交付。** 给两个文件的绝对路径 + 说明。用户后续要微调，优先改规格重新生成，保持全图一致。

## 命令

```bash
# 生成 pptx + png（最常用）
python scripts/archbuild.py build spec.json --out ./out --png

# 只做布局自检，不写文件；改规格时反复用这个
python scripts/archbuild.py check spec.json

# 把已有 pptx 重新导出 png（宽 2560，16:9 即 2560×1440）
python scripts/archbuild.py export deck.pptx --width 2560

# 用内置示例跑一张，确认环境正常
python scripts/archbuild.py demo --out ./out --png
```

退出码：`0` 正常；`1` 有 WARN（加 `--strict` 时）；`2` 有 ERROR。**看到 WARN 不要直接交付**，先按提示改规格。

## 规格速查

```json
{
  "title": "某某平台总体架构",
  "subtitle": "分层架构 · 应用与数据两级解耦",
  "canvas": "16:9",
  "rails": { "left": { "label": "标准规范体系" }, "right": { "label": "安全保障体系" } },
  "bands": [
    {
      "id": "app", "label": "应用层", "height_in": 1.12,
      "groups": [
        { "label": "业务应用",
          "items": [
            { "id": "biz",   "label": "事项办理", "tone": "accent" },
            { "id": "query", "label": "综合查询", "sub": "含历史数据" }
          ] }
      ]
    }
  ],
  "flows": [
    { "from": "biz", "to": "query", "label": "调用" }
  ],
  "legend": [ { "label": "重点模块", "tone": "accent" } ],
  "notes": ["支撑层与数据层物理上可合并部署"]
}
```

- **canvas**：`16:9`（默认，投屏用）、`4:3`、`a4l`、`a4p`，或 `{"w_in":13.333,"h_in":7.5}`。
- **bands**：从上到下一条一条排，每条是一个横向分层。`height_in` 省略时按 1.12in 自动分配；总高超出可用区会自动压缩并告警。
- **groups**：分层里的横向分组，带标题。分组宽度按模块数量和文字长度自动分配；`"span": true` 让它占满整层。
- **items**：模块。`label` 是主文字，`sub` 是第二行小字（技术栈、协议之类）。
- **tone**：`default` 一般模块 / `accent` 重点模块 / `strong` 强调（深底白字）/ `muted` 弱化 / `ghost` 外部系统 / `warn` 风险 / `ok` 正常。**全图 tone 不超过 3 种**。
- **shape**：`rounded`（默认）/ `rect` / `oval`。
- **free**：需要绝对定位时用，`{id,label,x_in,y_in,w_in,h_in}`。分层表达不了的结构（中心辐射、特殊拓扑）用它。
- **flows**：`from`/`to` 填 item 的 `id` 或 `label`；`style: "dash"` 画虚线（表示异步、可选、间接）；`label` 是线上文字。
- **rails**：左右两条竖向侧栏，放"标准规范体系""安全保障体系"这类横切关注点。

## 设计规范摘要

完整规范（配色表、字号阶梯、间距、图型配方）在 `references/design-spec.md`，写规格前读一遍。核心几条：

- **克制。** 一个主色 + 中性灰阶 + 最多两个语义色；强调色面积不超过 10%。同层级同色，不同层级靠底色深浅区分。
- **不要装饰。** 无渐变、无阴影、无发光、无 3D、无玻璃拟态、无图标堆砌。阴影在渲染器里已经强制关闭，不要加回来。
- **字要能读。** 模块名 11—12pt，说明 8—9pt，注释 8pt。渲染器会自动缩字号避免溢出，缩到 8pt 还放不下会告警——这时应该缩短文案或加宽模块，而不是继续缩。
- **对齐。** 同级模块等宽等高、间距一致。渲染器用统一网格，不要在 free 里手写不对齐的坐标。
- **连线。** 正交折线，箭头统一，不穿框、不穿文字。走线尽量落在层间空隙和模块间隙里。

## 自检清单

构建后按这个顺序过一遍，前五项看命令输出，后两项看 PNG：

1. 文字溢出告警：`文字放不下：'xxx'`
2. 连线穿框告警：`连线 x->y 仍然穿过 N 个模块`
3. 连线交叉计数：`交叉 N 处`。理想值是 0——**避免交叉是布线的第一优先**，不是 0 就先调模块顺序或删减连线
4. 标签压模块告警：`连线标签 'xxx' 压到模块`
5. 模块重叠 / 超出画布：直接是 ERROR，必须修
6. PNG 里层级是否一眼可辨（相邻层底色有没有区分开）
7. PNG 里有没有孤立的、不知道从哪连过来的线，图例/页脚/注释有没有互相压住

## 常见坑

- **PowerPoint COM 不接受中文路径。** 导出脚本已经把文件复制到 ASCII 临时目录再导出，所以不要在 `--out` 上纠结中文目录；但如果自己写导出命令，一定要先转 ASCII 路径，否则报 `DirectoryNotFoundException`。
- **模块太窄导致文字竖排。** 一格里塞两个以上模块时，单个模块宽度可能只有 1in。这时把 `sub` 去掉或把该组拆成两行。
- **连线穿框是因为结构本身没有通路。** 上下两层模块正好对齐、中间又挡着一个模块时，任何正交路径都要绕。解法是调整分组顺序，或把 `flows` 精简到真正重要的几条——不是所有依赖都值得画。
- **同一个模块同一条边上的多条连线**渲染器会自动错开落点，不需要手动调。
- **`flows` 里的 id 写错**会直接报 ERROR 并列出可选值，照着改即可。
- **不要为了"看起来丰富"加装饰。** 评审看的是一眼能读懂的层级和依赖，不是视觉密度。

## 文件说明

- `scripts/archbuild.py` —— 规格渲染器：布局、文字适配、正交避障布线、自检、COM 导出。读它比读文档更准。
- `references/spec-schema.md` —— 规格全部字段与默认值。
- `references/design-spec.md` —— 配色、字号、间距、图型配方、反例。
- `assets/example-layered.json` —— 一份可直接跑的完整分层架构示例。
