# 毕设论文流水线（bishe-lw）

把「一个代码库号」变成「仓库 `论文/` 目录下四个规范命名的文件」。

**分工**：
- 本技能负责它前后所有搬运、解析、档案匹配、质检、校验、上传
- 论文生产交给 `ty-lw-skill`（通用、格式档案驱动）
- `hbks-lw-skill` 不再被调用，河北科技师范学院只是档案库里的**一份档案**

## 硬约束（任何情况不许绕过）

1. **落盘位置唯一**：所有下载与产出的本地文件只能放在
   `D:\Tools_Home\DeepseekHarness_Load\lw\<代码库号>\` 下。不许写到别处。
2. **命名固定**：`学号_姓名_专业_题目`，上传四个文件：
   `<基名>.docx`、`<基名>.pdf`、`<基名>_可编辑版.docx`、`<基名>_可编辑版.pdf`。
3. **字段不许编造**：学号/姓名/专业/题目 缺任何一个 → 停下来问用户，补齐才允许推送。
   指导教师、学院缺失可以先生成，但必须在交付报告里点名。
4. **材料不齐直接报错**：`开题材料/` 里没有 `.docx`（只有 PPT）时，不硬写，报错让用户先补。
5. **格式只认档案**：排版格式全部来自 `format-profile.json`，脚本里没有学校常量。
   - 学校有档案 → 用档案
   - 学校没档案 → **拒绝开工**，让用户提供该校论文模板（除非显式 `--allow-baseline`）
   - **绝不允许**"拿 A 校的格式套 B 校的封面还当成对的"
6. **默认分支自动探测**：毕设仓库里 `bishe001/002` 是 `master`，`003–011` 是 `main`，
   绝不写死分支名。
8. **不许用 `--force` 重建工作区**：会清空已写好的 `manuscript.md`。要重建必须走 `--reinit`（自动备份）。

7. **文献口径（硬规范）**：
   - **优先采用任务书/开题报告里列出的参考文献**（`student.json` 的 `references`），
     并**联网在知网检索原文**核对；这些中文题录必须全部进参考文献，一条都不能漏；
   - 其余中文文献从云效仓库 `论文/论文推荐/` 里抽取，**不许引库外中文文献**；
   - 每篇论文参考文献**总数 15–35 篇**（`refs.min_total` / `refs.max_total`）；
   - **英文文献：河北科技师范学院只要 1 篇**，且必须是 `开题材料/外文原文` 那一篇；
     其他学校默认上限 3 篇（`refs.max_english`、`refs.english_by_school`）；
   - 题录缺作者/刊名/学校时：先**读仓库里该篇的 pdf/caj/md**；读不出可**联网按题名检索核对**，
     题名必须与库内精确一致、把来源 URL 记进 `.work/refs/meta-results.json`，再 `refs merge`；
   - 联网只补元数据/核对原文：**不许换文献、不许编造作者/刊名、不许按关键词自动插引用**；
   - 实在查不到的字段留空，期刊按 `[J/OL]`、学位论文按 `[D/OL]` 加知网链接著录；
   - 发布闸门逐条核对：条数区间、开题题录是否全部引用、中文是否全部来自文献库、
     是否引用了外文原文、英文是否超配额、是否缺作者。

## 两层结构（ty-lw-skill 的核心思想）

| 层 | 内容 | 会不会因学校而变 |
|---|---|---|
| **格式层** | `format-profile.json`：页边距、字体字号、行距、分节页码、页眉、题注、参考文献、字数区间 | **变**，由学校模板/规范提取 |
| **方法层** | 证据先行、硬性大纲、逐章成文、Visio 图、降 AIGC、三道闸门、双版本交付 | **不变**，全校通用 |

## 执行流程

### 第 0 步：确认学校档案（第一次遇到新学校时）

```bash
python "...\run.py" profile list               # 看档案库里有什么
python "...\run.py" profile show 河北科技师范学院
python "...\run.py" profile check 河北科技师范学院
```

**新学校**：拿到该校论文模板 `.docx`（最好含封面、样式、页码设置）后：

```bash
python "...\run.py" profile extract --school "河北工程技术学院" --template "该校论文模板.docx"
```

只有文字版规范（通知/PDF 转文字）：

```bash
python "...\run.py" profile spec --school "某某大学" --spec "格式规范.md"
```

两种都有：先 extract 打底，再 `--spec ... --base 已有档案.json` 补文字要求。

> 模板优先于规范文字；两者冲突时 `profile_diff.py` 会列出差异，**让用户裁决，不要自己选一个**。
> 提取不到就写 gap，**不要用默认值冒充学校要求**。

### 第 1 步：拉取仓库、解析开题材料、建参考文献库

```bash
python "...\run.py" init <代码库号>
```

一次跑完：解析仓库号 → 拉取任务书/开题报告/源码 → 解析作者字段 → **从仓库材料建参考文献库**
→ 匹配学校档案 → 建写作工作区。不再停下来问用户要文献。

文献库分三层（`config.yaml` 的 `refs` 段），**优先级从上到下**：

| 层 | 来源 | 说明 |
|---|---|---|
| 一、开题题录 | 任务书/开题报告里的 `references` | **必须全部引用**；联网在知网检索原文核对 |
| 二、仓库推荐 | `论文/论文推荐/NN-题名.md`（可附 `pdf/`） | 每篇 md 的题名、类型、年份、关键词、知网链接、推荐句、建议引用位置、摘要 |
| 三、英文 | `开题材料/外文原文*.pdf` | 必须引用；河北科技师范学院英文就这 1 篇 |

产出 `.work\refs\library.md`（分三节）与 `.work\refs\opening-sources.md`（开题题录原文检索清单）。
退出码 `3` 表示**开题题录 + 推荐文献也凑不够 `min_total`（默认 15）条**，这时不能开工。

### 第 1.1 步：开题题录取原文 + 题录补录

```bash
python "...\run.py" refs harvest 010    # 重新扫描（init 已自动跑过）
# 1) .work\refs\opening-sources.md：开题报告列的每条文献，逐条联网在知网检索原文，
#    取到后把 {id, url, got: true} 记进 .work\refs\opening-sources.json
# 2) .work\refs\missing-meta.md：缺作者/刊名的条目，标着该篇在仓库里的本地文件路径
python "...\run.py" refs merge 010      # 合并补录结果（题名对不上的一律丢弃）
python "...\run.py" refs lib 010        # 看库内齐全数
```

**开题题录**（第一优先）：题录本身已经写在开题报告里，`library.md` 里原样保留；
要做的只是联网在知网检索原文、确认这篇真实存在且内容对得上，取不到就在交付报告里点名。
**不许**因为检索麻烦就把它们删掉——它们必须出现在参考文献里。

**推荐文献的题录补录**（先本地、再联网）：

1. **先读仓库里的文件**：每条缺项都指向 `论文/论文推荐/` 下该篇的 pdf / caj / md——
   打开它，读封面或首页的作者、刊名、学校、年卷期页；
2. **读不出来再联网按题名检索**（知网、百度学术等），只用来核对这一篇的题录；
   题名必须与库内归一化后完全一致，把检索到的 URL 写进 `url` 字段留痕；
3. 把结果抄进 `.work\refs\meta-results.json`（已按缺口生成好空行），`confidence` 只写 `exact`；
4. `refs merge` 合并——题名对不上、或 `confidence` 不是 `exact` 的一律丢弃。

硬规则：

- 联网只补元数据/核对原文：**不许换文献、不许把检索到的别篇塞进库里、不许编造作者/刊名**；
- 网上查到但题名不完全一致的，当没查到，留空；
- 文献里确实没有的字段留空：期刊按 `[J/OL]`、学位论文按 `[D/OL]` 加知网链接著录。

`.work\refs\notes.md` 汇总了开题题录与每篇推荐文献的推荐原句、摘要，写作时按它支撑论断。

`refs merge` 之后可引用条目仍不足 15 条时，**停下来找用户**：请用户补文献 PDF/CAJ 或题录。
不许把库外文献塞进正文凑数。

### 第 2 步：写作用这批文献

写作时打开 `.work\refs\library.md`，正文引用编号与文末 `[n]` 必须一一对应：

- **第一节（开题题录）必须全部引用**，一条都不能漏——这是“优先采用”的硬要求；
- 其余中文文献从第二节里选，**不许引库外中文文献**；
- 英文文献**必须**含外文原文那一条（通常放绪论讲国外研究现状）；
  **河北科技师范学院英文就这 1 篇**，其他学校最多 3 篇（可加领域经典文献）；
- 全文条数控制在 **15–35 条**（`refs.min_total`–`refs.max_total`），
  引用位置参考每条下面的「建议引用位置」；
- 文献的支撑作用要写清：不要把题名当结论，也不要只凭关键词凑引用。

用户额外提供文献时（可选，非必需）：

```bash
python "...\run.py" refs accept 010 --files "D:\用户给的材料\文献1.pdf"
```

`refs accept` 只是把文件收进 `论文\文献\` 备查，**不会**自动进文献库；确要引用需人工确认后写进正文。

### 第 2.1 步：按 ty-lw-skill 写作（文献用 .work\refs\library.md）

写作前先核对：开题题录是否都进了库、`refs lib` 里可引用条目加上开题题录是否 ≥ 15 条。

- 正文里每个 `[n]` 都要能在 `library.md` 找到对应条目，文末 `[n]` 与正文一一对应；
- 引用要落到论点上：绪论讲国内外研究现状引用综述类，第 4 章设计引用方法类，
  第 6 章测试引用对比实验类——按每条下面的「建议引用位置」分配；
- **禁止**只凭共享关键词插 `[n]`、把文献题名当研究结论、或清空已有编号；
- 外文原文那一条放绪论国外研究现状，译文内容来自 `开题材料/外文翻译`；英文总数不超配额；
- 读不到全文的文献（只有 md 题录与摘要）只支撑综述性表述，不据此编造具体实验数据。

工作区保留 `student.json`、`materials-extracted.md`、`refs\`、`format-profile.json`、源码事实源、正文与图表。
字数区间取自档案 `word_budget`；朱雀检测、内容/格式验收与安全上传流程保留。

### 第 3 步：质检（朱雀 AIGC + 联网溯源查重）

写作完成后**必须先过质检再上传**。

#### 3.1 朱雀 AIGC 检测

```bash
python "...\run.py" detect 010
```

调用腾讯朱雀官方接口（EdgeOne Makers `@makers/zhuque-text`），
`is_merge=false` 拿到逐段结果。

**实测校准过的语义（官方文档写得不准，以实测为准）**：

| 字段 | 实测含义 |
|---|---|
| `label` | **1 = AI 生成，2 = 人工编写，0 = 疑似** |
| `labels_ratio` | **按字符数**算的三类占比；`labels_ratio["1"]` 就是 AI 率 |
| `position` | `[偏移, 长度]`，**不是** `[起点, 终点]` |
| 分段粒度 | 约 **250–320 字**，按句边界切 |
| `softmax_confidence` | 获胜类别的置信度，**不是**"人类概率"，别拿 `1-x` 当 AI 率 |
| `makers_models_usage` | 计费 token，约为正文字符数的 **1.67 倍** |

**判定粒度是 300 字，段内 AI/人工混排会稀释判定**——纯 AI 长文稳定判 100%，
纯人工稳定判 0%，但每个 ~300 字块里如果既有 AI 腔又有具体细节，整块会判人工。
所以改稿时**不要只改半句**，要整段重写。

> **口径声明（重要）**：以上语义来自**少量样本的当下实测**（4 组对照 + 若干真实稿），
> 只能说明"本次调用下检测器如此表现"，**不能证明它长期稳定**，也不代表其他检测器一致。
> AI 率是**辅助观察指标**，不是质量结论：低 AI 率 ≠ 事实正确、引用可靠、论文合格。
> 改稿的第一依据永远是**事实准确、表达清楚、作者能辩护**，而不是把某个分数压下去。
> 禁止为了降分虚构数据/文献/经历；也不要只针对单一检测器过拟合。

产出：
- `.work\quality\detect-<时间戳>.md` —— 人看的报告，含「需改写片段」原文清单
- `.work\quality\detect-<时间戳>.json` —— 机器用，含每段 conf 与原文
- `.work\quality\history.json` —— 历史 AI 率曲线

退出码：`0` 达标，`2` 未达标。

#### 3.2 按报告定点降重（核心循环）

**不要对着总分瞎改，按报告改标红段。** 每轮：

1. 读 `.work\quality\latest.json`，取 `flagged`（`label == 1` 的段），按 `conf` 降序
2. **整段重写，不要只改半句**（判定粒度 300 字，只改半句会被同段稀释掉，白改）
3. 按 `ty-lw-skill` 的 `references/05-humanize-standards.md` 做 **A1 脱稿重写**：
   拆句、换语序、加具体锚点（真实表名/接口名/字段名/测试数值/时间地点）、删套话
4. 攒够一批改动再重跑 `detect`（一次全量检测约 1.67 倍字符数的 token，别改一句测一次）
5. AI 率 ≤ 10% 停；最多跑 `quality.zhuque.max_rounds` 轮（默认 4）

**有效手段**：把概括句拆成带具体事实的短句；用真实表名/字段名/接口路径替换抽象描述；
补真实测试数值（QPS、耗时、准确率）；把"随着…的发展"这类开场换成具体问题。

**无效手段**：同义词替换、调换语序、加"我们""笔者认为"——朱雀看的是句法结构与信息密度，
换词不改变统计特征。

**禁止**：为降 AI 率虚构数据/文献/经历。改完的事实必须能在源码、任务书或测试记录里找到依据。

#### 3.3 联网溯源查重

```bash
python "...\run.py" plagiarize 010        # 生成待查句清单
# → Agent 逐句联网搜索，把结果写到 .work\quality\plagiarism\results.json
python "...\run.py" plagiarize-report 010 # 汇总出报告
```

知网/维普/万方都没有公开 API，这条路走的是**逐句搜原出处**：
脚本按"通用表述程度"给句子排风险（`随着…的发展`、`是一种`、`主要包括` 这类高分，
`本系统采用…` 这类低分），Agent 拿高分句去搜，命中原句即判定照抄。

结果写回格式：

```json
[{"id": 0, "matches": [{"url": "...", "title": "...", "snippet": "...",
   "verdict": "原文照抄"}]}]
```

`verdict` 只能是 `原文照抄` / `改写` / `无匹配`。

> ⚠️ **口径必须说清**：这是**抽样**结果，不等于知网重复率。知网比的是它的全文库
> （含未公开的学位论文），联网溯源只能查到公开网页。**不能拿这个数冒充知网查重率。**

> **判定要人工过一遍**：命中原句 ≠ 学术不端。合理引用（带引号/注明出处）、公共术语、
> 通用定义都会命中。报告只提供「匹配证据 + 来源链接」，**是否改写由人判断**；
> 需要正式查重结论时，仍须走学校指定的商业查重系统。

## 令牌与密钥

都存在 `C:\Users\<user>\.dsh\skills\bishe-lw\secrets.env`（本机文件，**已被 .gitignore 排除，不入库**）：

```

```

**朱雀多 Key 自动轮换**：`zhuque.py` 按「主 Key → BACKUP1 → BACKUP2」顺序试，
遇到 401/403（失效）、429（限流）或其它 4xx 自动切下一个，并记住最近可用的那把。
只有全部失效才报错。`python scripts\zhuque.py check` 会逐把探活、列出各自状态。

> 备用 Key 只写在 `secrets.env`，**不要写进 SKILL.md / MANUAL.md 等会入库的文档**。

朱雀 Key 获取：腾讯云 EdgeOne 控制台 → **Makers** → **Models** → **API Key** → 创建
（不用绑卡，每月 50 万 token 免费额度）。
计费口径：按正文字符数约 **1.67 倍** 扣 token，14000 字的论文一次检测约 23000 token。
所以**不要每改一句就全量重测**——攒一批改动再测。

## 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| HTTP 403 `Current token has no permission to api` | 令牌没勾 API 权限点 | 云效后台重建令牌 |
| HTTP 401（云效） | 令牌过期/被删 | 重建令牌 |
| `克隆失败` 认证错 | git 用户名写错 | 必须是 `your_yunxiao_user`，不是 `oauth2` |
| 找不到仓库 | 代码库号写得不对 | `yx.py repos` 看全量 |
| `上传前检查未通过` | 缺必填字段 | 按提示补 `--set` |
| `没有 .docx` | 开题材料只有 PPT | 让用户补任务书/开题报告 |
| `该校还没有论文格式档案`（退出码 7） | 档案库缺这份 | `profile extract` 补；或 `--allow-baseline` 凑合 |
| `档案校名…与实际学校…不一致` | 拿错档案了 | 换成该校档案，不要强行用 |
| `档案体检未通过` | profile 有 ERROR | `profile check` 看具体字段，改档案 |
| `工作区里已有正文`（退出码 8） | 重复 init 会毁稿 | 确认重建加 `--reinit`（自动备份） |
| `仓库只提供 N 篇推荐文献`（退出码 3） | 开题题录 + 推荐文献不足 15 条 | 让用户在仓库补文献或补题录，再重跑 init |
| 文献库 `缺作者/缺来源` 很多 | 推荐文献只有 md 题录、没附 PDF | 先读 `missing-meta.md` 指的本机 pdf/md；读不出再联网按题名核对，补录后 `refs merge` |
| 补录后仍显示未齐全 | 题名对不上 / `confidence` 不是 `exact` | 照库内题名一字不差地填；读不出就留空，按 [J/OL] 著录 |
| `参考文献只有 N 条` | 引用没凑够 15 条 | 补几条开题题录或推荐文献，但别超过 35 条 |
| `N 条中文参考文献不在仓库文献库里` | 引了库外中文文献 | 换回 `论文/论文推荐` 里的条目 |
| `没有引用外文原文那一篇` | 英文文献缺失 | 引 `开题材料/外文原文` 那一条（通常放绪论） |
| `英文文献 N 条，超过上限 M 条` | 英文引多了 | 压到配额内；河北科技师范学院只留外文原文 1 篇 |
| `开题报告里列的 N 条参考文献没有引用` | 漏了任务书/开题报告题录 | 逐条补进正文与文末；这些必须优先采用 |
| `参考文献 N 条，超过上限 35 条` | 引多了 | 压到 35 条以内，优先删弱的推荐文献 |
| `外文原文的题录还没确认` | PDF 自动识别不可靠 | 人工核对后改 `.work/refs/en-source.json`，重跑 harvest |
| 模板逆向报 `模板解析失败` | 模板本身异常 / ty-lw 脚本 bug | 先看 `profile extract` 报错；必要时换一份模板 |
| 朱雀 `Missing API key` | 没配 Key | 写进 `secrets.env` 的 `MAKERS_MODELS_KEY` |
| 朱雀 `Invalid API key` | Key 错了/被删 | EdgeOne 控制台重建 |
| 朱雀 429 | 调用过快 | 脚本已自动退避重试，仍失败就隔几分钟 |
| `[阻断] 朱雀 AI 率 … 高于目标` | 未过质检就上传 | 先改稿重测，或确认后加 `--force` |
