# 结构图规范（Visio 标准示例版）

> 本文件规定第 3–4 章所有结构图的**画什么、放哪里、长什么样、怎么生成**。
> 唯一视觉基准：`assets/标准示例图/` 下 10 张 PNG。目标不是“好看”，而是**黑白、简洁、可编辑、与正文对得上**。
> 注意：示例图里的实体属性图只演示风格；实际论文中 **E-R 图有几个实体，就要生成几张实体属性图**。

## 1. 视觉基线（从示例图逆向）

| 项 | 要求 |
|---|---|
| 背景 | 纯白，无网格、无水印、无阴影 |
| 线条 | 黑色，约 0.75–1 pt；不使用彩色、渐变、3D |
| 填充 | 白底；不使用主题色填充 |
| 字体 | 宋体；正文节点 9–11 pt；连线标签 8–9 pt；全部黑色 |
| 对齐 | 同类节点同宽同高、等距排列 |
| 连线 | 默认**只允许水平线或垂直线**，可以有 90° 折线，禁止斜线/曲线。**唯一例外：实体属性图**采用中心辐射直线（允许斜直线） |
| 箭头 | 流程图、架构图用实心三角箭头，箭头必须由源指向目标；用例图、E-R 图、模块图**不加箭头** |
| 留白 | 图内边距紧致，导出时按内容裁切，不保留大片 A4 空白 |
| 文件 | 必须同时产出 `.vsdx`（可编辑源）和 `.png`（插图） |

**禁止**：彩色主题、圆角过大、阴影、立体块、渐变、艺术字、英文花体、把截图当结构图；除实体属性图外，**禁止斜线段、斜箭头、随手拖出来的斜连线**。

## 3. 各类图的画法

### 3.1 用例图（图3.1 / 图3.2）

- 左侧一个火柴人参与者，右侧竖排用例椭圆；参与者与每个用例之间用**水平/垂直折线**连接，不加箭头。
- 用例文字用“动词+对象”，如“租赁下单”“订单管理”，不要写“用户模块”。
- 一个角色一张图；普通用户与管理员分开画，不要把两个角色塞进同一张图。
- 用例数量控制在 6–12 个；过多时按业务域拆图或合并同类项。

### 3.2 流程图（图4.1–4.4）

- 开始/结束用**圆角矩形或椭圆**；处理步骤用矩形；判断用菱形；分支线标注“是/否”。
- 主流程尽量一条直线向下（或向右），回环线走外侧，避免穿过其他节点。
- **所有连线只能横平竖直**：需要绕行时用 90° 折线，不准用斜线直接连两个节点。
- **箭头方向必须从上游指向下游**：开始→步骤→判断→分支→结束；回环箭头指回被重试的步骤。
- 判断框的两个分支都要有去向，且标注“是/否”；不能出现分支悬空或箭头指回判断框自身。
- 图4.1 是**开发过程**流程（需求分析→总体设计→数据库设计→功能开发→系统测试），不要画成业务下单流程。
- 图4.4 是**订单业务状态**流程，最后用一行小字注明取消/回滚规则。

### 3.3 架构图（图4.5）

- 左侧客户端（小程序端、管理端），中间后端服务（Spring Boot/REST API），右侧数据与外部能力（MySQL、文件存储、AI 工作流）。
- 连线标注协议或动作（HTTP/JSON、数据读写、图片上传、对比推荐）；箭头方向为客户端→后端→数据/外部能力。
- 后端服务下方可挂“鉴权/异常处理/业务分层”说明框，表示横切能力。
- 所有连线走直角折线，标签放在线段旁且不压线；不要把标签放在竖向总线上。
- 不画具体类名、包名；架构图讲“层与边界”，不替代类图。

### 3.4 功能模块结构图（图4.6）

- 顶部系统名，第二层按端/服务划分，第三层为功能模块。
- 第三层用**竖排文字窄框**（每个汉字一行），与示例图一致；不要横排挤成小字。
- 模块名与第 5 章实现小节一一对应；第 5 章没有的模块不要画进图。
- 连线为水平/垂直折线，不加箭头。

### 3.5 E-R 图（图4.7）

- 实体用矩形，联系用菱形，属性用椭圆；实体之间通过菱形联系连接。
- 联系两端标注基数（1、N、M 或 1:N、N:M），标注放在连线旁、不要压在实体边框上。
- 图4.7 画**总体 E-R**（核心实体 6–12 个即可）；连接线全部横平竖直，不加箭头，靠菱形和基数表达关系。
- 图4.7 的实体/联系名称必须与 4.3.2 文字、4.3.3 表名一致。

### 3.6 实体属性图（图4.8–图4.8+N−1）

- **每个实体一张图**，不是只画“用户”一张。图的数量必须等于图4.7中的实体数量。
- **版式固定为中心辐射式**（对照 `标准示例图/图4.8实体-属性图.png`）：
  - 实体矩形居中；
  - 属性椭圆围绕实体四周排布：顶部 1 个、上左/上右、左/右、下左/下右、底部 1 个（按属性数量取槽位）；
  - 实体与每个属性之间用**一条直线**连接，**允许斜直线**（这是全部图表规则中唯一的斜线例外）；
  - 不加箭头、不加折线总线、不加边框外框。
- 属性数量 3–8 个；只画业务上重要的字段，不要把 id、create_time 等审计字段全堆上去；字段明细放 4.3.3 三线表。
- 属性名必须能在 4.3.3 的字段表里找到对应字段；实体名必须与 E-R 图、4.3.2 文字、表名一致。
- 生成方式：改 `specs/entity-attributes.json` 的 `entities` 列表，然后运行 `gen_entity_attributes.py`（见 4.2）。生成器会自动做圆形槽位排布和“实体边界→椭圆边界”的直线连接。

## 4. 生成方式（推荐）

### 4.1 复制标准规格

把技能内 `assets/figure-specs/*.json`（含 `entity-attributes.json`）复制到项目的 `specs/`，只改文字、模块名、实体名和必要的坐标，**不要从零手画**。版式已经按示例图调好。

### 4.2 两条命令生成

```bash
# 1) 标准结构图（用例/流程/架构/模块/E-R）
python <skill>/scripts/gen_figures.py --spec-dir specs --outdir figs

# 2) 每个实体一张实体属性图（读 specs/entity-attributes.json）
python <skill>/scripts/gen_entity_attributes.py --spec specs/entity-attributes.json --outdir figs
```

输出：

```
figs/图3.1普通用户用例图.vsdx / .png
...
figs/图4.7系统总体E-R图.vsdx / .png
figs/图4.8用户实体属性图.vsdx / .png
figs/图4.9手机设备实体属性图.vsdx / .png
...
```

单张生成：

```bash
python <skill>/scripts/gen_figures.py --spec specs/fig4-2-login-flow.json --out figs/图4.2用户注册登录流程图
```

只校验规格、不启动 Visio：

```bash
python <skill>/scripts/gen_figures.py --spec-dir specs --check
python <skill>/scripts/gen_entity_attributes.py --spec specs/entity-attributes.json --check
```

### 4.3 规格 JSON 要点

- 坐标单位英寸，`x` 向右、`y` 向下，原点在内容左上角；导出时会按内容自动裁切。
- 节点类型：`box`、`roundbox`、`ellipse`、`diamond`、`actor`、`text`、`leaf`、`cylinder`。
- 连线：`from`/`to` 指向节点 id；`from_side`/`to_side` 取 `left/right/top/bottom/center`；分支回环用 `points: [[x,y], ...]` 指定拐点，拐点也必须是水平/垂直的直角拐点。
- 流程图建议加 `"sequence": ["开始id","步骤id",...,"结束id"]` 表示主流程顺序；`--check` 会验证每一对相邻节点都有同方向箭头，能直接抓出 `from`/`to` 写反。
- 常用样式：`size`（字号）、`dash`、`line_weight`、`bold`、`text_angle`、`align`、`label`、`label_xy`。
- 改完先跑 `--check`，再生成；生成后**必须打开 PNG 逐张看**：文字是否溢出、连线是否穿字、标签是否压框、图是否被裁切、线段是否全是横平竖直。

### 4.4 没有 Visio 时

- 脚本会报 `Dispatch("Visio.Application")` 失败。此时：
  1. 安装 Microsoft Visio（推荐，能直接交 `.vsdx` 源文件）；
  2. 或把规格 JSON 转成 draw.io 手工打开/导出（需自行保证风格一致）；
  3. **不要把 matplotlib/PIL 直出的位图冒充 Visio 结构图**，学校可能要求交可编辑源文件。

> **不要用 LibreOffice Draw 代替 Visio**：它导出的 `.vsdx` 在 Word 里 OLE 激活和矢量预览都不可靠，且与 Word 的版面度量不一致；本技能的 `embed_vsdx.py` 依赖 Visio 的 `Visio.Drawing.*` OLE 类。
>
> Visio 启动同样会读默认打印机做版面度量，`gen_figures.py` 已通过 `scripts/office_prepare.py` 提前隔离网络打印机。

## 5. 插入 docx 的规则

- Markdown 写法：`![图4.1　系统总体设计流程图](figs/图4.1系统总体设计流程图.png)`，题注在图片下方。
- 正文必须先有引导句：“……如图4.1所示。”再出现图；图后要有 1–3 句分析，不能只放图。
- 图宽默认 15 cm（`build_docx.py --img-max-width-cm` 可调），高度不超过 18 cm；横向长图若文字太小，优先增大图内字号，而不是无限放大图片。
- 图题注与图必须同页：`build_docx.py` 已设置图片段“与下段同页”；若 PDF 中仍分离，手动在图前分页或缩小图。
- 每张图完成后更新 `paper-context/figure-registry.json` 的 `status`（`spec_ready` → `generated` → `inserted`）。
- 图号按章连续：图3.1、图3.2、图4.1……；增删图后全文检索“图X.Y”同步修改。

### 5.0 PNG 与 VSDX 的分工（双版本）

`figs/` 同时保留 `.vsdx` 和 `.png`，两者不是重复文件：

| 文件 | 作用 |
|---|---|
| `.vsdx` | 可编辑源：交付给学校/导师留档；进可编辑版 docx（OLE）；后续改图从它改 |
| `.png` | 提交版 docx 的实际显示图；作图后的**检视图**（模型只能看 PNG）；WPS/在线预览/转换器的兼容兜底 |

- 提交版 `论文.docx` 插 PNG；可编辑版 `论文_可编辑版.docx` 用 `embed_vsdx.py` 把第3–4章结构图原位换成 VSDX OLE，第5章截图仍用 PNG。
- 两版必须同源（同一次 `build_docx.py` 产物派生），图号、图位置、题注一致。
- OLE 是 docx 内嵌副本，在 Word 里改图不会同步外部 `.vsdx`；长期维护要改 `specs/*.json` → 重新生成 → 重跑 `embed_vsdx.py`。
- 可编辑版导出 PDF 用 Word（`update_fields.py`），不要用 WPS/在线转换。

### 5.1 连线与逻辑自检（每张图必做）

**几何**：

- [ ] 除实体属性图外，所有线段都是水平或垂直，**没有一条斜线**（含箭头前的短引线）。
- [ ] 实体属性图：实体居中，属性椭圆围绕四周；每条连线都是实体边界→属性椭圆的**单段直线**（斜线允许），没有折线总线、没有箭头。
- [ ] 折线只有 90° 拐角；拐点不穿过节点框、不压在文字上。
- [ ] 箭头只出现在目标端；没有“双头箭头”“箭头指回自己”“箭头悬空”。
- [ ] 连线标签在线的旁边，不压线、不压框。

**逻辑**：

- [ ] 流程图有且只有一个“开始”和一个“结束”；开始无入边，结束无出边。
- [ ] 从“开始”出发能沿箭头到达每一个节点；没有孤立节点。
- [ ] 每个判断框的分支都有去向，且标注“是/否”等条件；没有悬空分支。
- [ ] 回环箭头指回需要重试的步骤（如“提示错误→重新输入”），不是指回“开始”。
- [ ] 架构图箭头方向是“调用/数据流”的方向：客户端→后端→数据库/外部能力。
- [ ] 用例图、E-R 图、模块图不加箭头；E-R 图基数标注与业务关系一致。

**自动检查**：

```bash
python <skill>/scripts/gen_figures.py --spec-dir specs --check
python <skill>/scripts/gen_entity_attributes.py --spec specs/entity-attributes.json --check
```

`gen_figures.py --check` 会报：非实体属性图的斜线段（含斜的 `points`）、缺目标箭头、主流程顺序与箭头方向不一致（`from`/`to` 写反）、缺开始/结束、开始有入边、结束有出边、从开始不可达、无法到达结束、判断分支未标注。
`gen_entity_attributes.py --check` 会报：实体属性图误用折线/箭头、属性数量超过 8 个、文字溢出。
发现问题先改规格，再重新生成；不要手工在 Visio 里拖线绕过检查。

**如果必须在 Visio 里手工修图**：

1. 除实体属性图外：选中连接线 → 右键“连接线类型” → 选“直角连接线”（不要“直线连接线”/“曲线连接线”）。
2. 删除所有手工拖出的自由线段，改用“连接线”工具从形状的连接点连到另一个连接点。
3. 箭头方向：选中线 → “线条”→“箭头”→ 起点/终点箭头，确认箭头在目标端。
4. 流程图/架构图等折线拐点必须是 90°；出现斜段就删掉重连，不要靠拖端点“凑”。
5. 实体属性图：用“直线连接线”，从实体矩形直接连到每个属性椭圆，保持中心辐射式，不要改成折线总线。
6. 改完重新导出 PNG，按 5.1 清单再看一遍。

## 6. 第五章界面截图占位

- 实现章每个功能小节至少 1 张最终界面截图；没有真图时先用占位：

```markdown
如图5.1所示，首页集中展示轮播图、推荐设备与快捷入口。

![图5.1　首页界面](PENDING:首页)
```

- `build_docx.py` 会把 `PENDING:xxx` 渲染成虚线占位框，题注正常编号。
- 提交前必须替换为真实截图：`![图5.1　首页界面](figs/首页.png)`；删除占位后重跑内容闸门与 docx 闸门。
- 截图要求：最终完成态、无测试脏数据、无水印错位、宽高不过大（默认 15 cm）、图注在下。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 图被裁掉/留白很大 | 内容坐标超出画布或未裁切 | 检查节点/`points` 坐标；脚本默认按内容裁切，若仍异常看是否有负坐标 |
| 文字溢出框 | 字号大/框太窄 | 加宽框、缩短文字或换行；`--check` 会提示 |
| 连线穿过文字 | 标签位置在线上 | 调整 `label_xy` 到线旁；不要给标签加白底（会切断线） |
| 箭头方向反了 | `from`/`to` 写反 | 交换 from/to，或改 `from_side`/`to_side` |
| 出现斜线/斜箭头 | 手绘或改了路由 | 用 `gen_figures.py` 重新生成；`--check` 会报斜线段（实体属性图除外） |
| 判断框分支没有“是/否” | 规格漏写 `label` | 给每个出边补 `label`，`--check` 会报 |
| 某个节点从“开始”走不到 | 漏连边或方向反了 | 补边并确认 from→to 是业务顺序 |
| 实体属性图画成折线总线 | 用了旧版生成器 | 用当前 `gen_entity_attributes.py`（中心辐射直线版）重新生成 |
| 实体属性图只有一张 | 只改了单个规格 | 改 `entity-attributes.json`，每个实体一条，跑 `gen_entity_attributes.py` |
| 竖排模块名倒了 | 用了 `text_angle: 90` | 标准做法是每个汉字一行（`"首\n页\n展\n示"`），不要旋转 |
| 生成的图不是黑白的 | 修改了样式或用了主题模板 | 只用本脚本/本规格，不要套 Visio 主题 |
| 没有 .vsdx | 只导出了 PNG | 脚本默认两者都产出；`--no-vsdx` 仅用于预览 |
